### 2. Разработка класса ApiClient
**Статус:** Выполнено
**Файл:** `backend/api/src/ApiClient.php`

Реализовано 5 методов для работы с API:
- `getCalcs()` - получение списка калькуляторов

- `runCalculation($calcId, $data)` - выполнение расчёта
- `addToCalculation($calcId, $data)` - добавление в калькуляцию
- `saveCalculation($calcId, $data)` - сохранение калькуляции

**Технические особенности:**
- Централизованная конфигурация base URL
- Автоматическая обработка JSON
- Информативные сообщения об ошибках
- Поддержка кастомных endpoints

### 3. Модернизация системы MockData
**Статус:** Выполнено
**Файл:** `backend/api/src/MockData.php`

Реализован гибридный подход с двумя режимами работы:

#### MOCK режим (тестовые данные)
- Используется по умолчанию для разработки
- Не требует подключения к внешним сервисам
- Мгновенный отклик
- Предсказуемые результаты

#### REAL режим (реальное API)
- Работа с продакшн сервером
- Автоматический fallback на mock при ошибках
- Логирование всех запросов
- Настройка через конфигурацию

**Методы управления:**
```php
MockData::enableRealApi($url);   // Включить реальное API
MockData::disableRealApi();      // Вернуться к mock
MockData::isUsingRealApi();      // Проверить текущий режим
```

## 🏗️ Архитектурные решения

### 1. Разделение ответственности
```
├── Router.php        → Маршрутизация запросов
├── Response.php      → Формирование ответов
├── MockData.php      → Провайдер данных (гибридный)
├── ApiClient.php     → HTTP клиент для API
└── config.php        → Централизованная конфигурация
```

### 2. Паттерн проектирования
- **Strategy Pattern** для переключения источников данных
- **Singleton Configuration** для настроек
- **Dependency Injection** в тестах

### 3. Обработка ошибок
```php
try {
    return ApiClient->getData();
} catch (Exception $e) {
    error_log($e->getMessage());
    return MockData::getFallbackData();
}
```

Система автоматически переключается на mock данные при:
- Недоступности API
- Таймауте запроса
- Ошибках сервера
- Проблемах с сетью
