## 1. Единицы измерения и диапазоны значений

### 1.1 Объемные буквы (калькуляторы 146, 155)

**Текущая реализация:**
- Высота буквы: 5-200 см (шаг 5 см)
- Ширина рамы: 0-5 м (шаг 0.1 м)
- Размеры подложки: 0-5 м (шаг 0.1 м)

**Вопросы:**
1. ✅ Правильно ли, что высота буквы указывается в **сантиметрах**? (API возвращает "см")
2. ✅ Правильно ли, что рама и подложка в **метрах**? (API возвращает "м")
3. ❓ Верны ли диапазоны:
   - Высота буквы: минимум 5 см, максимум 200 см?
   - Ширина рамы: максимум 5 метров достаточно?
   - Подложка: максимум 5х5 метров достаточно?
4. ❓ Шаг 5 см для высоты буквы - это технологическое ограничение или можно любое значение?
5. ❓ Шаг 0.1 м (10 см) для рамы/подложки - корректно или нужна большая точность?

## 2. Передача дробных значений

**Текущая реализация:**
- API принимает дробные числа (например, 1.5, 2.3)
- Пользователь может вводить с точностью до 0.1

**Вопросы:**
1. ❓ Нужна ли точность до **миллиметров** для вывесок (0.001 м = 1 мм)?
2. ❓ Или достаточно точности до **сантиметров** (0.01 м)?
3. ❓ Для букв: можно ли высоту 27.5 см или только кратно 5 см?

**Примеры значений, которые могут прийти в API:**
```json
// Вывеска
{"variable": "w", "type": 1, "value": 1.5}    // 1.5 м
{"variable": "h", "type": 1, "value": 2.3}    // 2.3 м

// Рама
{"variable": "rama_w", "type": 1, "value": 3.7}  // 3.7 м

// Буквы
{"variable": "sr_h", "type": 1, "value": 30}     // 30 см
```

### 5.2 Количество букв vs текст
**Вопросы:**
1. ❓ Если пользователь вводит текст "КАФЕ" (4 буквы), но поле "Количество" = 5, что приоритетнее?
2. ❓ Правильно ли, что мы считаем длину текста и игнорируем поле "Количество"?

```javascript
// Текущая логика:
const actualLetterCount = computed(() => {
  if (calculatorData.text && calculatorData.text.trim().length > 0) {
    return calculatorData.text.trim().length  // Берём длину текста
  }
  return calculatorData.num || 1  // Иначе количество
})
```
